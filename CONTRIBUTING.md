# Contributing

Thanks for helping improve the Isogate web client.

## Before opening a pull request

1. Read the relevant UI, API-client, and product-status code before changing it.
2. Keep changes narrowly scoped and explain behavior that affects wallet, API, or security boundaries.
3. Run `pnpm run typecheck` and `pnpm run build` locally when dependencies are available.
4. Do not include credentials, wallet keys, generated bundles, logs, node modules, source maps, or private operational data.
5. Use public or synthetic examples only. Do not make unverified audit, market, decentralization, or production-readiness claims.

## Pull requests

Use a clear title and describe the user-visible and compatibility impact. Include reproduction steps for fixes and note any API contract assumptions. Changes to generated API code should be accompanied by the source specification update in the appropriate public project.

By participating, you agree to follow the [Code of Conduct](./CODE_OF_CONDUCT.md).
